The installed app includes the project license and third-party notices in `Contents/Resources/licenses`, available before sign-in. The application icon uses the launcher’s own workspace mark. The launcher’s theme uses fonts installed on the Mac; it bundles no font or theme artwork. Electron supplies the native browser engine and sandboxed renderer. The CLI can run on a clean Mac because it carries Node. Neither requires a separately installed JavaScript runtime. The packager checks the architecture-specific SHA-256 digest of both upstream archives before unpacking them. Projects that redistribute a build must retain its notices and fulfill the applicable component source and license obligations, including the LGPL terms for the separately linked FFmpeg library. The published source and matching upstream dependency revisions allow rebuilding the launcher and replacing that library. Re-sign a locally modified bundle before running it.

The desktop download includes no Docker engine. The owner selects and installs their engine separately. Before distributing a new version, review the exact upstream binaries, credits and source availability again as part of the [packaged release checks](../docs/maintainers/releasing.md).

## Packaging tools

The build uses Electron’s MIT-licensed [@electron/asar 4.3.2](https://github.com/electron/asar/blob/e6217019ed4bcf2b4c274123abfc749e94897c9f/LICENSE.md) to pack the launcher and [@electron/fuses 2.1.3](https://github.com/electron/fuses/blob/00f2479b958d917fe0f6e7711e85f62b74b3e7c2/LICENSE) to configure the official Electron binary before signing. Both run on the build machine. The root lockfile records their exact dependency versions, digests and licenses, including MIT and Blue Oak Model License 1.0.0 dependencies. Their JavaScript stays in the build environment.

# Data Model: Install an App and Use It

New tables in Your Space's database (FR-024). App data itself lives in the app's named volumes.

## app

One row per app on this installation, kept after removal as the record of its retained data.

| Column | Type | Notes |
| --- | --- | --- |
| id | uuid | Primary key |
| name | text, unique | The app's short name: 1 to 30 of `a-z`, `0-9`, `-`, starting with a letter. Its origin is `<name>.<Your Space's host>` and its Compose project `ys-<name>`. |
| title | text | Shown in the interface |
| source_url | text | The link as given, or `sha256:<digest>` for a Compose file given on this machine (`install-app --compose`) |
| repo, path, ref | text | Parsed from the link. For a Compose file on this machine, `path` is its file name (empty from standard input), and `repo` and `ref` are empty |
| commit | text | The exact commit the link resolved to (FR-003); empty for a Compose file on this machine |
| compose | text | The app's file at that commit, or as given on this machine, unchanged |
| kit | jsonb, null | The installation kit used, as parsed. Every app installed since 2026-11-23 has one; null only for an app installed earlier without a kit |
| kit_source | text, null | The kit's link at its exact commit, or `sha256:<digest>` for a kit file given on this machine |
| images | jsonb | `{ "<ref>": { "digest": "sha256:…" } }` (FR-004) |
| adaptations | jsonb | `[{ "service", "kind": "changed" \| "left_out" \| "added", "detail" }]` |
| interface | jsonb, null | `{ "service", "port" }`; null when the app has no interface |
| pane | boolean | Whether it opens in a pane (default) or its own tab |
| publish | jsonb, null | `{ "port": 8081, "bind": "127.0.0.1", "link": "https://…" or null }` when the owner publishes the app on a port of this machine (decision 2026-11-19); null otherwise |
| frame | boolean | Whether Your Space shows the app, published with a link, in its pane, its Caddy letting only Your Space's origin frame it (default true, and true again when publishing stops; decision 2026-11-20) |
| limits | jsonb | `{ "<service>": { "memory": bytes, "cpus": number } }` |
| desired | text | `running`, `stopped` or `removed` |
| state | text | `installing`, `starting`, `running`, `degraded`, `stopped`, `failed` or `removed` |
| state_reason | text, null | Why, for `degraded`, `failed` and `stopped` |
| installed_by | uuid → actor | FR-025 |
| created_at, updated_at, removed_at | timestamptz | |

## app_setting

| Column | Type | Notes |
| --- | --- | --- |
| app_id, name | uuid → app, text | Primary key |
| value | text, null | AES-256-GCM ciphertext (`v1.<iv>.<tag>.<data>`, base64url); null when unset |
| secret | boolean | Shown only as set or not set |
| generated | boolean | Generated by Your Space (FR-006) |
| published_default | text, null | The file's default, kept only for settings that aren't secret |

## install_job

| Column | Type | Notes |
| --- | --- | --- |
| id | uuid | |
| app_id | uuid → app | |
| kind | text | `install`, `apply` (start, settings, limits, outbound changes) or `remove` |
| state | text | `running`, `succeeded` or `failed` |
| steps | jsonb | `[{ "at", "message" }]`, never secret values |
| error | text, null | |
| created_at, finished_at | timestamptz | |

A job left `running` when the server starts is marked failed with "Interrupted by a restart" (FR-012).

## event (changed)

Adds `subject_app_id uuid null → app (on delete set null)` and the types `app.installed`,
`app.settings_changed`, `app.limits_changed`, `app.publish_changed`, `app.outbound_approved`, `app.outbound_removed`,
`app.request_dismissed`, `app.removed` and `app.data_deleted`.

## Not stored

Install previews and pass handoff codes are kept in the server's memory (30 minutes and 60 seconds).
Passes are signed cookies. The adapted Compose file is rebuilt from the stored file, kit, pins,
settings and limits each time an app is applied, so secret values are never stored in it.

# Candidate acceptance walkthrough

Use a disposable workspace, an independent app installation and synthetic records. Record exact platform commit, integration build, app image and external agent version in local test evidence. Keep credentials and private app data out of evidence.

1. Open the web dashboard, install the pinned app, complete app-side owner linking, and inspect the roles declared by its kit. Create an agent named “Test agent” and issue its own key.
2. The owner injects the key into the selected external agent’s private environment as `YOUR_SPACE_AGENT_KEY` and sets `YOUR_SPACE_URL`. Give the agent the CLI and a reachable workspace address. Supply no personal login, app token, model secret from another system, or operator access. Redact the secret from tool traces, command echo and diagnostics. Keep each agent’s key independent.
3. Try discovery with zero grants. Grant read access for one installation. Ask the real agent to list records and attempt a write. Record the permitted read, denied write and unchanged app state.
4. Grant a kit role permitting create and edit. Accept the kit recommendation, then configure direct create and Ask on edit. Ask the agent to create one synthetic record, then edit a field on that record. Verify the edit is pending and the app still shows the previous value. Approve the exact change once in Your Space. Reopen the app and verify one stable record ID, the new field value and preservation of unrelated fields. Check the owner-visible activity records match the agent and app. Simulate a lost response and repeat with the same operation ID; verify exactly one record.
5. Enable Ask for all writes and confirm it overrides direct create. Reject one request, verify no upstream change, and confirm another agent cannot approve it. Verify that a second role cannot bypass the same route policy and no agent result exposes the app credential. Make a competing edit in the human UI and verify the stale agent edit conflicts. Confirm another installation and another agent cannot access the record. Reduce the grant while the original agent is running and repeat. Rotate its key, then disable the agent; verify the old key, then all keys, lose access as expected.
6. Repeat gateway access on localhost and over remote HTTPS. Exercise browser-published app access separately: it must confer no agent authority. Recheck grants after restart and uninstall/reinstall. Revoke the test credentials and remove them from the agent environment. Record observed outcomes and unsupported paths alongside synthetic CI results.
